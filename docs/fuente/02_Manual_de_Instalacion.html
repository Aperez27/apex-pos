1.Requisitos

ElementoRequisito
Sistema operativoWindows 10/11, Linux (Ubuntu, Debian, Fedora…) o macOS. Con Docker, cualquiera de ellos.
PHP8.1 o superior (probado en 8.2) con las extensiones pdo_mysql y mbstring.
Base de datosMariaDB 10.4+ o MySQL 8.
Servidor webApache 2.4 con mod_headers y AllowOverride All (recomendado: aplica los .htaccess de seguridad), o Nginx + PHP-FPM con la configuración de deploy/nginx-apex.conf.
NavegadorMicrosoft Edge, Google Chrome o Firefox actualizados.
InternetNecesario en los equipos que usan el sistema: estilos, íconos, ventanas de confirmación y el generador de PDF se cargan desde CDN.

2.Obtener el sistema

El código está en GitHub: https://github.com/Aperez27/apex-pos. Puedes clonarlo con Git o descargarlo en ZIP (Code → Download ZIP). El uso requiere licencia del autor (archivo LICENSE).

git clone https://github.com/Aperez27/apex-pos.git apex

La carpeta puede llamarse como quieras; en este manual se usa apex.

apex/
├── *.php                  módulos (ventas, caja, cartera, inventario, reportes…)
├── setup.php              instalador / actualizador de la base de datos
├── .htaccess              reglas de seguridad de Apache
├── config/                config.php (no editar) · config.local.example.php · conexion.php
├── includes/              encabezado, pie, lógica de caja, generador de Excel
├── logs/                  registro de errores
├── docs/                  manuales en PDF (docs/fuente: fuentes para regenerarlos)
├── deploy/                ejemplos de Apache, Nginx y script de base de datos
├── docker/, Dockerfile, docker-compose.yml, .env.example
└── tests/                 pruebas automáticas
No elimines los archivos .htaccessEstán en la raíz y en config, includes, logs, tests, deploy, docker, .github y docs/fuente. Impiden descargar desde el navegador la configuración, los registros, la carpeta .git y demás archivos internos.

3.Configuración

El archivo config/config.php no se edita (se actualiza con cada versión). Los datos de cada instalación se escriben en uno de estos dos medios, que nunca se suben al repositorio:

MedioCómoIdeal para
config/config.local.phpCopia config.local.example.php con ese nombre y escribe tus valores.XAMPP, servidores Linux
Variables de entornoAPEX_DB_HOST, APEX_DB_PORT, APEX_DB_USER, APEX_DB_PASS, APEX_DB_NAME, APEX_DEBUGDocker, hosting

Si existe config.local.php, tiene prioridad sobre las variables de entorno.

<?php
define('DB_HOST', 'localhost');
define('DB_PORT', 3306);
define('DB_USER', 'apex');
define('DB_PASS', 'una-clave-larga-y-segura');
define('DB_NAME', 'apex_db');
// define('APP_DEBUG', true);   // solo para diagnosticar

DB_USER / DB_PASSroot / (vacía)Usuario de MySQL. En producción usa uno propio (capítulo 13).
DB_NAMEapex_dbNombre de la base de datos.

El sistema trabaja en hora de Colombia (America/Bogota) en PHP y en MySQL, aunque el servidor esté en otra zona.

4.Instalar en Windows (XAMPP)

  1. Descarga XAMPP desde https://www.apachefriends.org (versión con PHP 8.2) e instálalo en C:\xampp con Apache, MySQL, PHP y phpMyAdmin.
  2. En el XAMPP Control Panel pulsa Start en Apache y MySQL. Para que arranquen con Windows: Config → Autostart, o instálalos como servicio (casilla Svc).
  3. Copia el sistema en C:\xampp\htdocs\apex (o clónalo ahí con Git).
  4. (Recomendado) Crea la base y un usuario propio: cambia la clave dentro de deploy\crear_base_mysql.sql y ejecuta: 
    C:\xampp\mysql\bin\mysql.exe -u root < C:\xampp\htdocs\apex\deploy\crear_base_mysql.sql
    Luego crea config\config.local.php (capítulo 3) con ese usuario y clave. Si omites este paso, APEX usa root sin contraseña, como viene XAMPP.
  5. Abre http://localhost/apex/setup.php: crea las tablas, los usuarios iniciales, el «Cliente General (Mostrador)» y cinco categorías de ejemplo (sin productos ni proveedores de ejemplo).
  6. Entra a http://localhost/apex (capítulo 8).
Puerto ocupadoSi Apache no arranca porque el puerto 80 está en uso (Skype, IIS…), cierra ese programa o cambia el puerto en httpd.conf (por ejemplo 8080) y entra con http://localhost:8080/apex.

5.Instalar en Linux (Ubuntu / Debian)

# 1. Paquetes
sudo apt update
sudo apt install -y apache2 mariadb-server php php-mysql php-mbstring git
sudo a2enmod headers

# 2. Código
sudo git clone https://github.com/Aperez27/apex-pos.git /var/www/apex

# 3. Base de datos y usuario (cambia la clave dentro del archivo antes)
sudo nano /var/www/apex/deploy/crear_base_mysql.sql
sudo mysql < /var/www/apex/deploy/crear_base_mysql.sql

# 4. Configuración local con la misma clave
sudo cp /var/www/apex/config/config.local.example.php /var/www/apex/config/config.local.php
sudo nano /var/www/apex/config/config.local.php

# 5. Permisos: solo logs/ es escribible por el servidor web
sudo chown -R root:www-data /var/www/apex
sudo chmod -R o-rwx /var/www/apex
sudo chown -R www-data:www-data /var/www/apex/logs

# 6. Sitio de Apache (edita ServerName)
sudo cp /var/www/apex/deploy/apache-apex.conf /etc/apache2/sites-available/apex.conf
sudo nano /etc/apache2/sites-available/apex.conf
sudo a2ensite apex && sudo systemctl reload apache2

# 7. Tablas
sudo -u www-data php /var/www/apex/setup.php

Con Nginx

Instala nginx php-fpm php-mysql php-mbstring y usa deploy/nginx-apex.conf, que repite en Nginx todas las reglas de seguridad de los .htaccess (Nginx no los lee). Ajusta la ruta del socket de PHP-FPM a tu versión.

Fedora / RHEL / Rocky

Paquetes: httpd mariadb-server php php-mysqlnd php-mbstring; el usuario del servidor web es apache y el sitio va en /etc/httpd/conf.d/apex.conf. Si SELinux está activo: sudo chcon -R -t httpd_sys_rw_content_t /var/www/apex/logs.

HTTPS

sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache

6.Instalar en macOS

  • Docker Desktop (recomendado): sigue el capítulo 7.
  • XAMPP para macOS: igual que en Windows, con el sistema en /Applications/XAMPP/xamppfiles/htdocs/apex y los programas en /Applications/XAMPP/xamppfiles/bin/ (mysql, php).
  • Homebrew: brew install php mariadb httpd; en httpd.conf habilita mod_headers, el módulo de PHP y AllowOverride All para la carpeta del sistema; luego los pasos 3, 4 y 7 de Linux.
No uses php -S en producciónEl servidor integrado de PHP no aplica las reglas de .htaccess; sirve solo para pruebas locales.

7.Instalar con Docker

Funciona igual en Windows, Linux y macOS. Requiere Docker Desktop (Windows/macOS) o Docker Engine (Linux).

git clone https://github.com/Aperez27/apex-pos.git apex
cd apex
cp .env.example .env          # Windows PowerShell: copy .env.example .env
# edita .env y cambia APEX_DB_PASS y DB_ROOT_PASS
docker compose up -d

Abre http://localhost:8080. Se crean dos contenedores:

ServicioQué es
dbMariaDB 10.11 con la base apex_db y el usuario apex; los datos persisten en el volumen apex_datos.
appApache + PHP 8.2 con el sistema. Al arrancar espera la base y ejecuta setup.php (crea o actualiza las tablas).

Comandos útiles

docker compose ps                                    estado
docker compose logs -f app                           registro del sistema
docker compose exec db mariadb-dump -u apex -p apex_db > respaldo.sql
docker compose down                                  detener (los datos se conservan)
git pull && docker compose up -d --build             actualizar

Para publicarlo en internet, ponlo detrás de un proxy con HTTPS (Nginx, Caddy, Traefik) y cambia APEX_PUERTO si el 8080 está ocupado.

8.Primer ingreso y puesta a punto

UsuarioContraseña inicialRol
adminadmin123Administrador
vendedorvendedor123Vendedor
Cambio obligatorioEstas contraseñas son públicas. Al ingresar con ellas, el sistema obliga a cambiarlas (mínimo 8 caracteres, distinta a la inicial y al usuario) antes de permitir usar cualquier módulo.
  1. Entra con admin / admin123 y define la nueva contraseña.
  2. Configuración: nombre real de la empresa, NIT, teléfono, dirección y mensaje del ticket.
  3. Usuarios: crea un usuario para cada vendedor (o entra con vendedor y cámbiale la contraseña).
  4. Inventario → Categorías: renombra o elimina las de ejemplo y crea las tuyas.
  5. Proveedores: regístralos indicando qué suministra cada uno.
  6. Inventario: crea los productos con sus colores y stock.
  7. Caja: abre la primera caja con la base en efectivo y empieza a vender.

Protección del instalador

Una vez instalado, setup.php solo lo puede ejecutar un administrador con sesión iniciada o la consola (php setup.php). Ejecutarlo varias veces es seguro: solo agrega lo que falte y no borra datos.

9.Copias de seguridad

Desde el sistema

Menú Backup DB → Descargar Backup SQL. Genera backup_apex_AAAAMMDD_HHMMSS.sql con toda la estructura y los datos.

Automática en Windows

Crea C:\respaldos\backup_apex.bat y prográmalo a diario en el Programador de tareas:

@echo off
set F=%date:~-4%%date:~3,2%%date:~0,2%
"C:\xampp\mysql\bin\mysqldump.exe" -u apex -pTU_CLAVE apex_db > "C:\respaldos\apex_%F%.sql"
forfiles /p "C:\respaldos" /m apex_*.sql /d -30 /c "cmd /c del @file"

Automática en Linux

sudo mkdir -p /var/backups/apex
sudo crontab -e
0 22 * * * mysqldump -u apex -p'TU_CLAVE' apex_db > /var/backups/apex/apex_$(date +\%F).sql && find /var/backups/apex -name 'apex_*.sql' -mtime +30 -delete

Docker

docker compose exec db mariadb-dump -u apex -p apex_db > respaldo.sql
ConfidencialLos respaldos contienen toda la información del negocio, incluidos los usuarios. Guárdalos fuera del servidor web (nunca en htdocs ni /var/www) y conserva una copia semanal fuera del equipo.

10.Restaurar una copia y mover de equipo

mysql -u apex -p apex_db < respaldo.sql             (Windows: C:\xampp\mysql\bin\mysql.exe)
php setup.php                                        (deja la estructura al día)

También desde phpMyAdmin: base apex_db → Importar → archivo .sql. En Docker: docker compose exec -T db mariadb -u apex -p apex_db < respaldo.sql.

Mover el sistema a otro equipo

  1. En el equipo viejo: descarga un backup y copia la carpeta del sistema (incluido config/config.local.php).
  2. En el equipo nuevo: instala según tu sistema (capítulos 4 a 7).
  3. Crea la base vacía, restaura el backup y ejecuta php setup.php.

11.Actualizar a una versión nueva

  1. Descarga un backup de la base de datos.
  2. Actualiza el código: git pull, o reemplaza los archivos conservando config/config.local.php.
  3. Ejecuta php setup.php (o ábrelo como administrador) para aplicar los cambios de estructura.
  4. Con Docker: git pull && docker compose up -d --build (el contenedor ejecuta setup.php solo).
  5. Revisa el historial de cambios en CHANGELOG.md.

12.Usar el sistema en red local

Otros computadores, tabletas o celulares conectados a la misma red pueden usar el sistema:

  1. Averigua la IP del equipo servidor (ipconfig en Windows, ip a en Linux), por ejemplo 192.168.1.50. Conviene fijarla en el router.
  2. Permite el puerto 80 (u 8080 con Docker) en el firewall: en Windows, «Permitir» cuando Apache lo pregunte; en Linux, sudo ufw allow 80/tcp.
  3. Desde los otros equipos entra a http://192.168.1.50/apex (Docker: http://192.168.1.50:8080).
Varios usuarios a la vezEl sistema controla que dos personas no vendan el mismo último producto, que dos abonos no superen el saldo, que no se abran dos cajas y que nada se registre en una caja que se está cerrando.

13.Puesta en producción y seguridad

APEX ya incluye:

  • Contraseñas cifradas (bcrypt), mínimo 8 caracteres, cambio obligatorio de la contraseña inicial y bloqueo de 15 minutos tras 5 intentos fallidos.
  • Sesiones con cookie protegida, renovación al ingresar y cierre por inactividad.
  • Token anti-falsificación (CSRF) en todos los formularios, consultas SQL parametrizadas y salida escapada contra XSS.
  • Cabeceras de seguridad (CSP, anti-clickjacking, nosniff) y bloqueo de carpetas internas, .git y archivos de configuración.
  • Errores ocultos al usuario y registrados en logs/php_errors.log; instalador bloqueado una vez instalado.

Lista de verificación

✔Tarea
☐Usuario MySQL propio con contraseña (deploy/crear_base_mysql.sql) y config.local.php con esos datos.
☐Contraseña asignada a root de MySQL (en XAMPP viene vacía).
☐Contraseñas iniciales de admin y vendedor cambiadas.
☐APP_DEBUG en false.
☐HTTPS si el sistema es accesible desde internet.
☐phpMyAdmin solo accesible localmente (XAMPP: Require local en httpd-xampp.conf) o desinstalado.
☐Copias de seguridad automáticas diarias y una copia semanal fuera del equipo.
☐Comprobado que /config/, /logs/ y /.git/ responden «Forbidden» (403).
☐Sistema operativo, XAMPP / paquetes y Docker actualizados.

Opcional: en producción puedes eliminar las carpetas tests y docs/fuente (las descargas de Releases ya no las incluyen).

14.Verificar la instalación

El sistema incluye pruebas automáticas. Requieren bash + curl (en Windows, Git Bash) y, para las de navegador, Python con Playwright:

bash tests/e2e.sh              (≈140 pruebas HTTP: ventas, caja, descuadres, permisos, seguridad)
python tests/ui_test.py        (≈47 pruebas en navegador: pantallas, PDF, celular, XSS)

Usan un administrador temporal (zzadmin) y datos con prefijo ZZ que se eliminan al final; no tocan las cuentas reales y, si hay una caja abierta, no la cierran. Variables opcionales: APEX_URL, MYSQL_BIN, PHP_BIN, MYSQL_USER, MYSQL_PASS, APEX_DB_NAME, APEX_BROWSER.

# Linux, ejemplo
pip install playwright && playwright install chromium
APEX_URL=http://localhost MYSQL_USER=apex MYSQL_PASS=TU_CLAVE bash tests/e2e.sh

15.Solución de problemas

SíntomaCausa y solución
«Error de conexión a la base de datos»MySQL apagado o datos incorrectos en config/config.local.php (o en las variables de entorno). Revisa usuario, contraseña, host y DB_NAME.
El login dice «Base de datos no disponible»La base aún no existe: ejecuta setup.php.
«APEX ya está instalado» al abrir setup.phpNormal. Para actualizar la estructura entra como administrador y vuelve a abrirlo, o ejecuta php setup.php.
«Ocurrió un error»Revisa la última línea de logs/php_errors.log. Para ver el detalle en pantalla pon temporalmente APP_DEBUG en true.
Linux: errores al escribir el registroLa carpeta logs debe pertenecer al usuario del servidor web: sudo chown -R www-data:www-data logs.
Se puede abrir /config/, /logs/ o /.git/ desde el navegadorApache ignora los .htaccess: pon AllowOverride All para la carpeta del sistema, activa mod_headers y reinicia. En Nginx usa deploy/nginx-apex.conf. Deben responder 403.
Se ve sin estilos o sin íconosEl equipo no tiene internet (los estilos vienen de CDN).
«Demasiados intentos fallidos»Bloqueo de 15 minutos por contraseñas erradas. Espera o, si es urgente: DELETE FROM login_intentos;
Olvidé la contraseña del administradorDesde otro administrador, cámbiala en Usuarios. Si no hay otro: genera un hash con php -r "echo password_hash('NuevaClave2026', PASSWORD_DEFAULT);" y actualiza la columna password del usuario (y pon debe_cambiar_clave=1 para que la cambie al entrar).
Docker: el contenedor app se reiniciadocker compose logs app. Suele ser que .env no existe o las claves no coinciden; tras cambiar la clave de la base hay que borrar el volumen (docker compose down -v, se pierden los datos) o cambiarla dentro de MariaDB.
Fechas u horas desfasadasRevisa la hora del equipo; el sistema trabaja en hora de Colombia.
El PDF del cierre no se descargaSin internet no carga el generador; usa Imprimir → «Guardar como PDF».
