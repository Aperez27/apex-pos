1.Visión general

APEX es una aplicación web monolítica en PHP 8 procedimental, sin framework, con renderizado del lado del servidor y base de datos MariaDB/MySQL vía PDO. Cada módulo es un archivo .php que procesa sus formularios (POST) y genera su HTML. La interfaz usa Bootstrap 5, Font Awesome y SweetAlert2 desde CDN.

CapaTecnología
ServidorApache 2.4 + PHP 8.2 (XAMPP), .htaccess con cabeceras de seguridad
DatosMariaDB 10.4 / MySQL 8, InnoDB, utf8mb4, PDO con sentencias preparadas reales
InterfazBootstrap 5.3, Font Awesome 6.5, SweetAlert2 11, JavaScript sin dependencias
ExportaciónExcel .xlsx generado en PHP puro (includes/xlsx.php); PDF del cierre con html2pdf.js en el navegador
PruebasBash + curl (tests/e2e.sh) y Python + Playwright con Edge (tests/ui_test.py)

3.Ciclo de una petición

  1. require 'config/conexion.php' → carga config.php, abre la sesión segura, exige login (si no, redirige a index.php), controla la inactividad, genera el token CSRF, conecta a la BD y recarga nombre y rol del usuario desde la base (si fue eliminado, cierra la sesión).
  2. Control de permisos del módulo ($rol !== 'admin' → «Acceso denegado» o redirección).
  3. Procesamiento de POST: csrf_verify(), validación, escritura en transacción cuando aplica y redirección con flash_redirect() (patrón Post/Redirect/Get: recargar la página no repite la operación).
  4. Consultas de lectura y include 'includes/header.php'.
  5. HTML del módulo (toda salida de datos pasa por h()) e include 'includes/footer.php'.

Las páginas independientes (ticket.php, caja_reporte.php) incluyen conexion.php pero generan su propio HTML para impresión. Las exportaciones envían el archivo y terminan.

4.Configuración y arranque

config/config.php no se edita en cada instalación. Primero carga config/config.local.php si existe; luego define con defined() || define() cada constante que falte, tomando las variables de entorno APEX_DB_HOST, APEX_DB_PORT, APEX_DB_USER, APEX_DB_PASS, APEX_DB_NAME y APEX_DEBUG o los valores por defecto. Constantes: DB_*, APP_NAME, APP_AUTHOR, APP_VERSION, SESION_INACTIVIDAD_MIN, PASSWORD_MIN y APP_DEBUG. Además:

  • Zona horaria America/Bogota en PHP y SET time_zone='-05:00' en cada conexión, para que NOW() y CURDATE() coincidan con PHP.
  • Con APP_DEBUG=false: display_errors=0, errores a logs/php_errors.log y un set_exception_handler que registra la excepción y muestra una página genérica (HTTP 500).
  • app_session_start(): cookie APEXSESSID con HttpOnly, SameSite=Lax, Secure automático bajo HTTPS y use_strict_mode.
  • app_pdo(): PDO con excepciones, FETCH_ASSOC y EMULATE_PREPARES=false.

Instalador / migrador

setup.php es idempotente: CREATE TABLE IF NOT EXISTS y ALTER TABLE … ADD COLUMN envueltos en try (si la columna ya existe, se ignora). Para añadir un cambio de esquema en una versión nueva se agrega al bloque de migraciones con un comentario de versión. Acceso: CLI siempre; web solo si la base no tiene usuarios (primera instalación) o si el visitante es un administrador con sesión.

5.Base de datos

Base apex_db — 14 tablas InnoDB utf8mb4. Líneas azules: clave foránea con ON DELETE CASCADE; líneas grises punteadas: relación lógica controlada por la aplicación.

Puntos clave

  • id_caja en ventas, abonos y caja_chica liga cada operación a la sesión de caja en la que ocurrió. Los registros previos a la versión con cajas tienen id_caja NULL.
  • pagos_venta guarda el desglose del pago (una fila por método; los pagos mixtos tienen varias). ventas.estado guarda la forma de pago principal.
  • caja_chica registra todo el dinero real: ventas y abonos por medios de caja, gastos e ingresos manuales y ajustes de descuadres (ajusta_caja = caja descuadrada a la que corresponde el ajuste).
  • No hay borrado de ventas: los productos, clientes y usuarios con historial no se pueden eliminar desde la aplicación.

6.Ventas y formas de pago

ConstanteValoresSignificado
METODOS_CAJAEfectivo, Transferencia, TarjetaDinero recibido: genera un ingreso en caja_chica con su metodo.
METODOS_CARTERATerceros, Credito InternoSuma a ventas.saldo_pendiente; se cobra luego con abonos.
FORMAS_PAGOlas anteriores + MixtoMixto exige que la suma de pagos coincida con el total (±0,02).

Proceso de cobro (ventas.php)

  1. Validaciones previas: caja abierta, stock del carrito, forma de pago, cliente existente, entidad para Terceros, cliente registrado y autorizador para Crédito Interno, suma del mixto.
  2. Transacción: bloqueo de la caja abierta (caja_abierta_bloqueada), inserción de la venta con id_caja, filas de pagos_venta y detalles_venta.
  3. Descuento de stock con UPDATE … SET stock=stock-? WHERE id=? AND stock>=?; si no afecta filas, se revierte («Stock insuficiente»).
  4. Obsequios: precio 0 y registro en inventario_movimientos.
  5. Ingresos en caja_chica por cada pago con método de caja; commit.

El carrito vive en $_SESSION['carrito'] con claves p{id} (vendido) y g{id} (obsequio).

7.Caja: sesiones y cuadre

  • Solo puede existir una caja con estado='Abierta'. caja_abrir() usa GET_LOCK('apex_abrir_caja') para evitar dos aperturas simultáneas.
  • La caja no tiene cierre automático: ningún cálculo depende de la fecha, todo se agrupa por id_caja.
  • Ventas y abonos requieren caja abierta; los gastos/ingresos manuales y los ajustes son exclusivos del administrador.
  • Apertura y cierre los pueden hacer vendedor y administrador.

caja_resumen($pdo, $caja)

Devuelve ventas con sus ítems y pagos, abonos, movimientos manuales (incluye ajustes registrados en esa caja), totales por medio y por origen (ventas/abonos/ingresos/egresos), ventas por forma de pago con desglose por entidad de Terceros, productos consolidados, cartera generada y el efectivo esperado:

efectivo_esperado = monto_inicial + Σ ingresos(Efectivo) − Σ egresos(Efectivo)   (en caja_chica, id_caja = caja)

Cierre

En una transacción se bloquea la fila de la caja, se calcula el esperado (incluyendo cualquier operación que estuviera en curso) y se guardan efectivo_esperado y efectivo_contado como fotografía del arqueo; luego se redirige a caja_reporte.php?id=N&cerrada=1, que descarga el PDF automáticamente.

8.Descuadres y ajustes

Un descuadre es una caja cerrada con |efectivo_contado − efectivo_esperado| ≥ 0,01. No es una tabla aparte: se calcula en caja_descuadres():

  • tipo: Faltante si contado < esperado; Sobrante en caso contrario. monto = valor absoluto de la diferencia.
  • ajustado: suma de caja_chica.monto con ajusta_caja = id y tipo Ingreso (faltante) o Egreso (sobrante).
  • pendiente = monto − ajustado; estado Pendiente o Cuadrado (fecha del último ajuste).

Cuadrar (caja.php, POST cuadrar_descuadre): solo administrador, requiere caja abierta. En una transacción bloquea la caja abierta y la caja descuadrada, recalcula el pendiente, valida 0 < monto ≤ pendiente e inserta en caja_chica un movimiento con id_caja = caja abierta, ajusta_caja = caja descuadrada y referencia_origen = 'Ajuste caja #N'. Se permiten ajustes parciales.

Los descuadres se muestran en el Dashboard, en Caja (pendientes y en el historial de cierres), en caja_reporte.php (el propio y los pendientes de otras cajas), en Reportes y en exportar_descuadres.php.

9.Concurrencia

RiesgoSolución
Dos aperturas de caja simultáneasGET_LOCK con nombre alrededor de la verificación e inserción.
Venta, abono o movimiento registrado mientras se cierra la cajaSELECT … FOR UPDATE sobre la caja abierta dentro de la transacción; el cierre también bloquea la fila, así que se serializan y nada cae en una caja ya cerrada.
Vender el último producto dos vecesUPDATE … WHERE stock >= cantidad y verificación de rowCount().
Dos abonos que juntos superan el saldoRelectura de saldo_pendiente con FOR UPDATE dentro de la transacción.
Dos ajustes que superan el pendienteBloqueo de la caja descuadrada y recálculo del pendiente dentro de la transacción.

10.Seguridad

11.Reportes Excel y PDF

Excel (includes/xlsx.php)

Genera .xlsx (OpenXML en ZIP) sin librerías externas. API principal:

$x  = new Xlsx('Título');
$sh = $x->sheet('Hoja');
$x->header($sh, 'Título', ['línea 1', 'línea 2'], $columnas);
$x->kpis($sh, [['Etiqueta', $valor, 'money'], …]);
$x->table($sh, [['Columna', 'money', 16], …], $filas, ['label' => 'TOTAL', 'sum' => [3]], ['red' => fn($f) => […]]);
$x->download('archivo.xlsx');

Tipos de columna: text, money, int, pct, date, datetime, center. Los totales usan SUBTOTAL() para respetar los filtros.

PDF del cierre

caja_reporte.php es HTML imprimible; el botón «Descargar PDF» usa html2pdf.js (cdnjs) en el navegador con tamaño carta y saltos de página que evitan cortar filas. Sin internet cae a window.print().

12.Interfaz (frontend)

  • Campos de dinero: todo <input type="number" step="0.01"> se convierte (en footer.php) en un campo de texto con separador de miles; el input original queda oculto con el valor limpio que llega al servidor. Excluir con data-no-format.
  • Confirmaciones: cualquier <form> o <a> con data-confirm="mensaje" (y opcional data-confirm-btn) muestra SweetAlert antes de enviar.
  • Mensajes: los .alert-dismiss generados por PHP se convierten en toast (éxito) o ventana (error).
  • Diseño adaptable: menú lateral desplegable bajo 1024 px; probado sin desborde horizontal a 390 px.

14.Mantenimiento y extensión

Agregar un módulo

  1. Crear modulo.php: require 'config/conexion.php', control de rol, handlers POST con csrf_verify() y flash_redirect(), luego include 'includes/header.php', HTML con h() y footer.php.
  2. Agregar el título en $pageTitles y el enlace con nav_link() en includes/header.php (dentro del bloque admin si corresponde).
  3. Cambios de esquema: agregarlos a setup.php de forma idempotente.
  4. Agregar pruebas en tests/e2e.sh y, si hay interfaz, en tests/ui_test.py.

Regenerar los manuales

bash docs/fuente/preparar_demo.sh          (copia de demostración + base apex_demo)
python docs/fuente/capturas.py             (capturas en docs/fuente/img)
python docs/fuente/generar_pdf.py          (PDF en docs/)
rm -rf /c/xampp/htdocs/apex_demo_manual    (limpieza)
mysql -u root -e "DROP DATABASE apex_demo"

Los textos están en docs/fuente/*.html y los estilos en manual.css. La demo nunca usa la base real.

Convenciones

  • Textos, comentarios e identificadores de negocio en español.
  • La marca siempre desde APP_NAME / APP_AUTHOR / app_copyright().
  • Dinero en DECIMAL(12,2); en PHP redondear a 2 decimales antes de comparar.
